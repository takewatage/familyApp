# テスト手順書 - ユーザー個別設定編集機能

## 概要

このドキュメントでは、ユーザー個別設定編集機能のテスト手順を記載します。

### テスト方針

**人間が実際に操作して確認することを最優先とします。**

自動テスト（ユニットテスト等）はAIが書いたコードをAIがテストすることになり、仕様の誤解や認識のズレを検出しにくい。人間が手順に沿って操作し、目で見て確認することで「意図した通りに動くか」を担保します。

- 手動テスト: すべての機能要件・受け入れ条件について、人間が操作手順で確認する
- 自動テスト: 手動で確認が困難な項目（バリデーション境界値・不正アクセス）に限定する

## 前提条件

- 開発サーバーが起動済みであること（`sail up -d` でコンテナ起動後、`sail yarn dev` でVite起動）
- テスト用ユーザーでログインできること
- DBマイグレーションが適用済みであること（`sail artisan migrate`）

## 手動テスト

### ケース 1: 初回表示（設定未保存の状態）

**対応要件:** F-1, F-3

**手順:**

1. テスト用ユーザーでログインする
2. マイページ（`/mypage`）に遷移する
3. 「設定」セクションが表示されていることを確認する
4. テーマのデフォルト値を確認する

**期待結果:**

- 「設定」セクションが表示されている
- テーマ: 「システム設定に合わせる」が選択されている

**確認結果:**

- [ ] OK / NG

**備考:** `users.settings` が NULL の場合のデフォルト値確認

---

### ケース 2: 設定を変更して保存する

**対応要件:** F-2, F-3

**手順:**

1. マイページに遷移する
2. テーマを「ダーク」に変更する
3. 「設定を保存」ボタンを押す

**期待結果:**

- 保存中はボタンがローディング状態になる
- 「設定を保存しました」スナックバーが表示される
- ページリロード後も「ダーク」が選択されたまま保持されている

**確認結果:**

- [ ] OK / NG

---

### ケース 3: 設定変更後にページをリロードして設定が保持されているか確認

**対応要件:** F-1, F-2

**手順:**

1. ケース 2 の手順で「ダーク」に変更・保存する
2. ブラウザをリロード（F5 または Ctrl+R）する
3. マイページのテーマ設定を確認する

**期待結果:**

- テーマ: 「ダーク」が選択されている

**確認結果:**

- [ ] OK / NG

---

### ケース 4: 設定をデフォルト値に戻す

**対応要件:** F-2, F-3

**手順:**

1. マイページに遷移する
2. テーマを「システム設定に合わせる」に変更する
3. 「設定を保存」ボタンを押す
4. リロード後に「システム設定に合わせる」が選択されていることを確認する

**期待結果:**

- テーマ: 「システム設定に合わせる」に戻っている

**確認結果:**

- [ ] OK / NG

---

### ケース 5: プロフィール編集と設定編集の独立性確認

**対応要件:** F-1, F-2

**手順:**

1. マイページでプロフィール（名前など）を変更して保存する
2. 設定セクションの値が変わっていないことを確認する
3. 設定を変更して保存する
4. プロフィールの値が変わっていないことを確認する

**期待結果:**

- プロフィール編集と設定編集が互いに影響しない

**確認結果:**

- [ ] OK / NG

## 自動テスト（手動で確認が困難な項目のみ）

### 不正アクセス防止（Feature テスト）

他ユーザーの設定を書き換えられないことを確認します（手動では検証しにくい）。

```bash
sail artisan test --filter=UserSettingsTest
```

```php
// tests/Feature/UserSettingsTest.php
public function test_user_cannot_update_other_users_settings(): void
{
    $user = User::factory()->create();
    $otherUser = User::factory()->create();

    $this->actingAs($user)
        ->post('/mypage/settings', [...])
        ->assertStatus(200); // 自分の設定は更新できる

    // 他ユーザーの設定を直接書き換えるルートが存在しないことを確認
    // （ルート自体がユーザーパラメータを取らない設計なので自動保護される）
}

public function test_invalid_settings_values_are_rejected(): void
{
    $user = User::factory()->create();

    $this->actingAs($user)
        ->post('/mypage/settings', [
            'taskDefaultSort' => 'invalid_value',  // 不正値
            'taskShowCompleted' => true,
            'theme' => 'system',
            'notifyTaskUpdate' => true,
        ])
        ->assertSessionHasErrors(['taskDefaultSort']);
}
```
