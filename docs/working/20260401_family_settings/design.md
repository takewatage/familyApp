# 家族設定機能 設計書

## 概要

マイページに家族設定メニューを追加する。以下の3機能で構成する。

| メニュー         | 概要                                             |
|----------------|--------------------------------------------------|
| 家族設定変更     | 家族名・最大メンバー数などの基本情報を変更する       |
| メンバー管理     | 実ユーザー一覧・仮想ユーザーの追加・ユーザー招待     |
| 家族切り替え     | 複数所属している家族グループを切り替える            |

---

## 1. 用語定義

| 用語           | 英語表記        | 定義                                                                 |
|--------------|---------------|----------------------------------------------------------------------|
| 仮想ユーザー   | VirtualUser   | アプリにログインせずにタスクや予約の担当者として割り当てられる家族内の人物   |
| アクティブ家族 | ActiveFamily  | ユーザーが現在操作対象としている家族グループ                             |

---

## 2. 機能要件

### F-010: 家族設定変更

- **対象者**: オーナーのみ編集可。他メンバーは閲覧のみ
- **編集項目**:
  - 家族名（`Family.name`）
  - 最大メンバー数（`Family.max_members`）
  - 家族コード再生成（既存コードを無効化し新しいコードを発行）

### F-011: メンバー管理

#### 実ユーザー管理

- 所属メンバー一覧（名前・アバター・ロール表示）
- メンバー除名（オーナーのみ操作可、自分自身は除名不可）
- ユーザー招待: 家族コードを表示・コピー。QRコード表示も検討

#### 仮想ユーザー管理

- 仮想ユーザー一覧表示
- 仮想ユーザーの追加（名前のみ必須、アバター画像は任意）
- 仮想ユーザーの編集・削除
- タスクや予約の担当者として選択可能にする（将来対応）

### F-012: 家族切り替え

- 所属している家族グループ一覧を表示
- 選択した家族をアクティブ家族に切り替える
- アクティブ家族の情報は `users.settings` の `activeFamilyId` に保存

## 4. データベース設計

### 新規テーブル: `virtual_users`

| カラム名       | 型           | 制約                          | 説明                     |
|--------------|-------------|-------------------------------|--------------------------|
| id           | UUID        | PK                            | UUID主キー               |
| family_id    | UUID        | FK → families.id, INDEX       | 所属家族                 |
| name         | string(50)  | NOT NULL                      | 表示名                   |
| created_at   | timestamp   |                               |                          |
| updated_at   | timestamp   |                               |                          |

- `files` テーブルとのポリモーフィック関係でアバター画像を管理（`fileable_type = 'App\Models\VirtualUser'`）

### `families` テーブル変更

`code_expires_at` カラムを追加する。

| カラム名          | 型          | 制約     | 説明                          |
|----------------|------------|---------|-------------------------------|
| code_expires_at | timestamp | nullable | 招待コードの有効期限（null = 無期限）|

- コード再生成時に有効期限を同時に設定する
- 有効期限切れのコードで参加しようとすると 422 エラーを返す
- 有効期限のUIは再生成ダイアログで選択（無期限 / 24時間 / 7日間 / カスタム日時）

### `users.settings` JSONスキーマ変更

既存の `settings` JSONカラムに `activeFamilyId` を追加する。

```json
{
  "theme": "light",
  "activeFamilyId": "uuid-of-active-family"
}
```

- ユーザーが初めてログインしたとき、最初に所属した家族を `activeFamilyId` に設定する
- `activeFamilyId` が null の場合は最初の所属家族を使用する（後方互換）

### `family_user` ピボットテーブル（変更なし）

既存のロール管理は変更なし。

| role 値   | 意味                     |
|----------|--------------------------|
| `owner`  | 家族を作成したオーナー      |
| `member` | 通常メンバー              |

## 5. API設計

### 家族設定変更

| エンドポイント          | メソッド | 説明                         |
|----------------------|---------|------------------------------|
| `/family/settings`   | GET     | 家族設定ページ（Inertia）      |
| `/family/settings`   | PATCH   | 家族基本情報の更新             |
| `/family/code/regenerate` | POST | 家族コード再生成             |

**PATCH `/family/settings` リクエスト**:
```json
{
  "name": "田中家",
  "max_members": 5
}
```

### メンバー管理

| エンドポイント                      | メソッド | 説明                            |
|----------------------------------|---------|----------------------------------|
| `/family/members`                | GET     | メンバー管理ページ（Inertia）      |
| `/family/members/{user}`         | DELETE  | メンバー除名（オーナーのみ）       |
| `/family/virtual-users`          | POST    | 仮想ユーザー作成                  |
| `/family/virtual-users/{virtualUser}` | PATCH | 仮想ユーザー更新              |
| `/family/virtual-users/{virtualUser}` | DELETE | 仮想ユーザー削除            |

### 家族切り替え

| エンドポイント             | メソッド | 説明                               |
|-------------------------|---------|-------------------------------------|
| `/families/switch`      | GET     | 家族切り替えページ（Inertia）         |
| `/families/{family}/switch` | POST | アクティブ家族の切り替え           |

## 8. 実装順序

1. **DB**: `virtual_users` テーブルのマイグレーション作成
2. **モデル**: `VirtualUser` モデル・リレーション追加（`Family` → `VirtualUser`）
3. **DTO**: 各DTOクラス作成（TypeScript型生成まで）
4. **ポリシー**: `FamilyPolicy` 作成・登録
5. **コントローラー**: 4つのコントローラーを順番に実装
6. **ルート**: `web.php` にルート追加
7. **フロント**: Vueページ・コンポーネント実装（画面順に）
   - マイページへの家族設定メニュー追加
   - 家族設定変更ページ
   - メンバー管理ページ
   - 家族切り替えページ
